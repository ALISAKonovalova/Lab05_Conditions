## Ответы на вопросы

**1. Чем `int.TryParse()` безопаснее `int.Parse()`? В каких случаях стоит использовать каждый?**
`int.Parse()` при вводе текста вместо числа просто «уроняет» программу с ошибкой. `int.TryParse()` в этом случае спокойно вернет `false`, и программа продолжит работать. `int.Parse()` можно брать, только если на 100% уверен в данных (например, они уже проверены). Для ввода от пользователя всегда нужен `int.TryParse()`.

**2. Когда `switch` удобнее, чем цепочка `if/else`? Приведите пример из реальной жизни.**
`switch` удобнее, когда мы проверяем одну и ту же переменную на кучу заранее известных вариантов. Например, выбор пункта в меню или нажатие кнопок на пульте: `case 1` — включить, `case 2` — выключить, `case 3` — переключить канал. Это читается намного проще, чем десять `else if` подряд.


**3. Что произойдёт в `switch`, если убрать `break` после одного из `case`?**
программа просто не скомпилируется — выдаст ошибку. Компилятор запрещает «проваливаться» из одного заполненного `case` в другой, чтобы защитить от случайных багов. Убрать `break` можно только у пустых `case`, если нужно объединить несколько значений под одно действие.

**4. Чем отличается `=` от `==` в C#? Почему это частая ошибка?**
`=` — это присваивание (записываем значение в переменную, например `x = 5`). `==` — это сравнение (проверяем, равно ли `x` пяти). Новички часто путают их из-за математики, где один знак `=` означает равенство. В коде из-за этого вместо проверки можно случайно перезаписать переменную.

**5. Можно ли написать тернарный оператор внутри другого тернарного оператора? Приведите пример из кода лабораторной и оцените читаемость такого кода.**
Да, можно. Пример из лабораторной:
`string weather = temp >= 20 ? "тепло" : (temp >= 0 ? "прохладно" : "мороз");`
Читается еще нормально, потому что тут всего три варианта. Но если вложить друг в друга больше операторов, код превратится в кашу, в которой легко ошибиться. Для сложных условий лучше использовать обычный `if/else`.
